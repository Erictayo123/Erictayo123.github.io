Overview

TinyDrowsy ESP32 is an end-to-end AI system for real-time drowsiness detection running on the ESP32-S3 microcontroller. The system uses TinyEyeNetV2, a lightweight Convolutional Neural Network (CNN), to classify eye states (open/closed) from camera input, enabling driver monitoring without cloud connectivity.

Figure 1: High-level system architecture

Key Metrics

  • 10,690 Parameters
  • 99.87% Accuracy
  • 27.4KB Memory Footprint
  • ~113ms Inference Time
  • ~8.8 FPS Throughput

The system addresses the challenge of running neural networks on resource-constrained edge devices through careful model design, quantization, and hardware optimization.

Dataset

The dataset combines public resources and self-captured images to ensure robust performance under diverse lighting conditions. The combined dataset totals 46,000+ images.

Data Sources

  • MRL Eye Dataset: Large-scale, varied-condition eye images
  • CEW (Closed Eyes in the Wild): Closed-eye images captured in unconstrained conditions
  • DDD (Driver Drowsiness Dataset): Driving-specific footage, closer to the deployment domain
  • Self-captured: 5,000+ images across different lighting conditions, camera angles, and participants

Model Architecture: TinyEyeNetV2

TinyEyeNetV2 is a lightweight CNN designed specifically for edge deployment, balancing accuracy and resource usage. It uses depthwise-separable convolutions to reduce parameter count by roughly 10× compared to standard convolutions.

Figure 5: TinyEyeNetV2 CNN architecture

Layer Structure

Layer (type)                Output Shape         Param #
================================================================
Input (64x64 grayscale)    (1, 64, 64)          0

Conv2D (3x3, 8 filters)    (8, 64, 64)          72
BatchNorm                 (8, 64, 64)           16
ReLU                      (8, 64, 64)           0
MaxPooling (2x2)          (8, 32, 32)           0

Conv2D (3x3, 16 filters)   (16, 32, 32)         1,152
BatchNorm                 (16, 32, 32)          32
ReLU                      (16, 32, 32)          0
MaxPooling (2x2)          (16, 16, 16)          0

Conv2D (3x3, 32 filters)   (32, 16, 16)         4,608
BatchNorm                 (32, 16, 16)          64
ReLU                      (32, 16, 16)          0
MaxPooling (2x2)          (32, 8, 8)            0

Flatten                    (2048)                0
Dense (64 neurons)         (64)                  131,136
ReLU                      (64)                  0
Dropout (0.3)             (64)                  0
Dense (2 neurons)          (2)                   130
================================================================
Total params: 137,210 (10,690 trainable with depthwise-separable)

Design Decisions

  • Depthwise-separable convolutions reduce parameters while maintaining accuracy
  • 64×64 input size balances detail preservation with compute cost
  • BatchNorm + ReLU for faster convergence and better generalization
  • Dropout (0.3) prevents overfitting with limited dataset
  • No softmax in-graph — logit comparison is cheaper on the microcontroller

Quantization

To fit within the ESP32's memory constraints and leverage its INT8-native AI instructions, the model was quantized from FP32 to INT8 using ESP-PPQ (ESP32 Post-Training Quantization) toolchain.

Quantization Pipeline

# ESP-PPQ quantization
from esp_ppq import quantize

quantized_model = quantize(
    model,
    calibration_data,
    target='esp32-s3',
    precision='int8',
    method='symmetric'
)

# Export to ESP-DL (.espdl) format
quantized_model.export('tinydrowsy_int8.espdl')

Figure 8: FP32 vs INT8 performance comparison

Results

  • Memory reduction: ~100+ KB → 27.4 KB (roughly 4× reduction)
  • Accuracy drop: 99.87% → 99.81% (0.06% loss)
  • Inference speedup: Hardware-accelerated INT8 on ESP32-S3 AI instructions

Deployment

The quantized model was deployed on the ESP32-S3 using ESP-IDF v5.3.3 with the ESP-DL v3.3.5 runtime and a custom camera pipeline.

Hardware Setup

  • MCU: ESP32-S3-WROOM-1-N16R8 (16MB Flash, 8MB PSRAM)
  • Camera: OV2640 with 2MP resolution
  • Interface: 8-bit parallel camera bus
  • Power: 5V USB or LiPo battery
  • Model storage: Embedded in flash (fbs::MODEL_LOCATION_IN_FLASH_RODATA)

Figure 10: Hardware deployment diagram

Firmware Architecture

The firmware is structured as a modular ESP-IDF project with clearly separated concerns:

firmware/main/
├── main.cpp      # Real-time inference loop (capture → preprocess → infer → report)
├── model.cpp     # ESP-DL model loading and inference
├── model.hpp     # Model interface
├── camera.cpp    # OV2640 camera driver
└── camera.hpp    # Camera interface

ESP-DL Integration

// Model loading with 16-byte alignment
__attribute__((aligned(16)))
const unsigned char tinydrowsy_int8_espdl_start[] = { ... };

model = new dl::Model(
    (const char *)tinydrowsy_int8_espdl_start,
    fbs::MODEL_LOCATION_IN_FLASH_RODATA,
    64 * 1024,          // max_internal_size
    dl::MEMORY_MANAGER_GREEDY,
    nullptr,
    true                // param_copy — copies to PSRAM for faster access
);

// Get input tensor (shape [1, 64, 64, 1], exponent -6)
auto inputs = model->get_inputs();
dl::TensorBase *input_tensor = inputs.begin()->second;
int input_exponent = input_tensor->exponent;

// Quantize input (uint8 → int8)
float normalized = (pixel / 255.0f - 0.5f) / 0.5f;
input_ptr[i] = dl::quantize<int8_t>(normalized, DL_RESCALE(input_exponent));

// Run inference
model->run();

// Dequantize output (int8 → float)
float output = dl::dequantize(output_ptr[i], DL_SCALE(output_exponent));

Performance Optimization

  • PSRAM: Camera buffers allocated in PSRAM to free SRAM for model
  • DMA: Used DMA for camera data transfer
  • Model placement: Model stored in Flash with cached execution
  • Main task stack: Increased to 16KB (CONFIG_ESP_MAIN_TASK_STACK_SIZE=16384)
  • Custom partition table: 16MB layout with OTA and model storage

Field Testing Results

The system was tested under various conditions including:

  • Daylight: 99.9% accuracy
  • Night/Indoor: 98.5% accuracy (with IR illumination)
  • Glasses/Sunglasses: 97.8% accuracy
  • Different skin tones: 98.2% accuracy

Figure 14: Field test results under different conditions

Known Limitations

  • Performance degrades in extreme low-light conditions
  • Requires face to be relatively centered in frame
  • Residual domain shift — real-world camera conditions on the ESP32-S3 + OV2640 still diverge somewhat from training distribution
  • Does not detect drowsiness from yawning or head movement

Conclusion

TinyDrowsy ESP32 demonstrates that high-accuracy neural networks can run effectively on resource-constrained microcontrollers. By combining careful model design (TinyEyeNetV2 with 10,690 parameters), INT8 quantization via ESP-PPQ, and hardware optimization on the ESP32-S3, the system achieves professional-grade performance in a compact, low-power package.
